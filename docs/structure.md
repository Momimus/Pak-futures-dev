# Project Structure Guide

This guide explains how the modular theme workspace is organized after unpacking a Blogger theme and how the pieces relate to one another during packing.

## High-Level Model

- The original theme is a single XML document with HTML + Blogger namespaces and special tags (`<b:section>`, `<b:widget>`, `<b:includable>`, `<b:include>`, `<b:skin>`, `expr:*`, `data:*`).
- The unpacker splits that document into small, focused files while leaving a lightweight scaffold (`main.html`) with informative placeholder comments that point back to each fragment.
- The packer reads `main.html`, resolves placeholders by loading the referenced files, and reconstructs a valid Blogger theme XML.

## Directory Layout

```
project/unpacked/
├── includables/
│   ├── all-head-content.xml          # <b:include name="all-head-content"/>
│   └── defs/                          # All <b:includable> definitions
├── inline-styles/                     # Each inline <style> becomes a CSS file
├── sections/                          # Each <b:section> as its own file
├── widgets/                           # Each <b:widget> as its own file
├── main.html                          # Skeleton (head/body, placeholders)
├── script.js                          # Inline scripts in tagged blocks
├── styles.css                         # Pure CSS, no <Variable> markup
└── variables.json                     # Theme variables + groups as JSON
```

## Placeholders And Labels

- In `main.html` and inside other fragments, structural elements are replaced by comments of the form:
  - `<!--SECTION sections/home-ad-top1.xml | CODEX_PLACEHOLDER …-->`
  - `<!--WIDGET widgets/LinkList70.xml | CODEX_PLACEHOLDER …-->`
  - `<!--INCLUDABLE includables/defs/widget-title.xml | CODEX_PLACEHOLDER …-->`
  - `<!--INLINE_STYLE inline-styles/style-1.css | CODEX_PLACEHOLDER …-->`
  - `<!--SCRIPT script-2 (head) | CODEX_PLACEHOLDER …-->`
- The left-hand label is human-friendly and usually Ctrl/Cmd‑clickable in editors; the right-hand `CODEX_PLACEHOLDER …` contains the metadata the packer reads to restore the element.
- Do not delete or hand-edit the `| CODEX_PLACEHOLDER …` tail.

## Fragment Types

- Sections (`sections/*.xml`)
  - The outer containers that Blogger’s Layout editor exposes; hold widgets and layout HTML.
  - Attributes you’ll see: `id`, `name`, `class`, `maxwidgets`, `showaddelement`.
  - You can add HTML or Blogger tags inside a section file; they will be packed as-is.

- Widgets (`widgets/*.xml`)
  - Content units inside sections with `type`, `title`, `visible`, and an inner `<b:widget-settings>` block.
  - Many widgets render via includables (see below) and accept `expr:*` bindings.

- Includables (`includables/defs/*.xml`)
  - Reusable templates for widgets/regions, defined with `<b:includable id="…">…</b:includable>` and used by `<b:include …/>`.
  - Heavily used by core Blogger widgets and custom templates.

- Inline Styles (`inline-styles/*.css`)
  - Every `<style>` block from the original theme is moved here.
  - Any attributes on `<style>` (e.g., `media`, `id`) are preserved when packing.

- Inline Scripts (`script.js`)
  - Each inline `<script>` becomes a labeled range:
    - `// [SCRIPT:script-3]` … `// [END SCRIPT]`
  - Keep both markers intact; the packer uses them to reinsert code.

- Global CSS + Variables (`styles.css`, `variables.json`)
  - Variables are represented as a list of entries with `entry_type` (`variable` or `comment`) and optional `group` metadata. The packer regenerates `<Group>/<Variable>` markup.
  - `styles.css` contains only CSS rules.

## Naming And Sanitization

- Filenames derive from Blogger `id`/`title` where possible; characters are sanitized to `A–Z a–z 0–9 _ . -` and collisions receive numeric suffixes.
- Moving/renaming a fragment file requires updating the corresponding placeholder label path in the parent fragment (e.g., a section that references a widget). Do not change the `| CODEX_PLACEHOLDER …` part.

## Editing Workflow

- Typical edits
  - Change styles in `styles.css` and inline styles in `inline-styles/*.css`.
  - Adjust variables in `variables.json` (values, groups, comments).
  - Update scripts inside `script.js` between the markers.
  - Modify markup inside `sections/*.xml`, `widgets/*.xml`, and `includables/defs/*.xml`.

- Adding new content
  - New HTML within an existing section: add it directly to that section’s XML.
  - New widget in a section: add a `<b:widget …>…</b:widget>` inside the section file; packing will include it. A subsequent unpack will split it into its own `widgets/*.xml` file automatically.
  - New includable: add the `<b:includable …>` block to an appropriate defs file or a new file under `includables/defs/`, then reference it with `<b:include …/>` in your widget/section.

- Avoid manual placeholder authoring
  - Placeholders are generated by the unpacker. If you need a new placeholder, prefer to add the real Blogger element; after packing and re-unpacking it will be split and labeled correctly.

## Packing And Validation

- Run `python3 scripts/pack_theme.py project/unpacked project/packed/theme-rebuilt.xml`.
- Run the provided verification snippet (see `docs/scripts.md`) to compare counts of sections/widgets/includables and ensure there are no stray placeholders or inline styles left in `main.html`.
